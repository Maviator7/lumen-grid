# Data supply and growing demand — 2026-10-30

Approved direction: an existing data center can serve a compact city; growing demand and distance make additional centers useful. Preserve freedom to use any reachable source, rather than requiring every facility to be connected. Scope is main continuous mode; keep the fixed tutorial and seed generator's legacy validation unchanged.

Main-mode demand by district: industrial 2 packets/s, residential 1.5/s, medical 3/s. Initial total 6.5/s. Each data center can dispatch 7 packets/s, with at most one packet of stored send credit. Initial center has modest spare capacity; even the smallest new district raises total to 8/s, exceeding one center. Additional centers use the same bounded output.

Create requests according to each district's demand, regardless of reachable capacity. A waiting request retains its original birth time and 5-second deadline; output shortage must cause waiting/expiry, never silently reduce offered demand. Dispatch oldest requests first to reachable centers that have output credit, preferring shorter paths and falling back to other centers. Unroutable requests fail. Separate source output credit from existing node/link processing credit. Count both waiting and travelling requests in bounded queues. Live topology edits retain deadlines; explicit reset clears queue/credits/counters. Expansion does not refill old centers. Reference planning clones copy per-node supply/demand parameters.

Expose main total demand, installed output capacity, disconnected/idle capacity, send-wait count; per-center dispatched rate and output limit; per-district requested rate and recent delivery. Show capacity shortage separately from route/processing congestion. Data centers are supply facilities and do not have to receive packets. Their own electricity consumption is outside this increment.

Balance acceptance: root solution stable on a sample of generated seeds. On seed 291026, expand north, connect all reference wiring but disconnect north center: power remains 100%, finite requests continue to expire, recent data falls below 90%, expansion stays locked. Reconnect center: output is used, queues recover, reliability >=90%, latency <=2.8s and stable45 unlock resumes. Repeat north/south reference expansion across six seeds six times; preserve existing time/wiring/reset and legacy checks. No progress save is added.

Metric timing: recent success rate counts outcomes resolved in the last 15 seconds: successful deliveries / (successful deliveries + failures). Pending and travelling requests are unresolved and shown separately; every queued request must eventually deliver or fail at its original deadline, so output shortages cannot erase offered demand. FIFO scans all requests per tick to avoid head-of-line blocking across independent centers.

Measured tuning: main-mode relay capacity has a minimum of 18 (legacy tutorial remains 16 at the central hub). At 16, the 12345 reference city after four expansions could deliver 100% but settled just above 2.8s due to a saturated root relay. Two additional processing slots restore modest headroom while the original shared power/data topology still congests. Reference expansion wiring uses a data-only crossing and power-only final east feeder, within the existing +2 dedicated slots per sector. Impossible-to-arrive requests remain pending until their original deadline; they do not waste source output that can still serve feasible requests.
