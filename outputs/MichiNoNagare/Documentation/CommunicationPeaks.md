# 通信ピークとデータセンター増強（2026-11-11）

左の「通信ピーク設定」で有効・無効を選び、適用する。既存の都市は無効のまま読み込み、新規生成は有効で始める。既存の街・配線・電力需要ルール・通信期限を変更しない。

有効化から90秒の準備後、30秒間の通信ピーク。以後120秒周期で繰り返す。停止中・設定画面中は時計も止まる。再有効化は新たに90秒の準備時間を取る。同じ設定を適用して時計を戻すことはできない。

| 区画 | 通常 | 通信ピーク |
|---|---:|---:|
| 住宅 | 1.5件/s | 3件/s |
| 工業 | 2件/s | 3件/s |
| 医療 | 3件/s | 3件/s |

観測ツールでセンターを選ぶと増強できる。初期1枠、2回の拡張ごとに1枠追加。増強は出力7→11件/s、追加電力2MW。追加出力4件/sは電力の供給率に比例し、電力ゼロなら基本7件/sへ戻る。共用・送電専用回線で電力も届ける。センターは通過施設として新たに使えるようにはしない。標準へ戻すと追加電力を停止し、増強枠を返す。通信ピークを無効にしても増強と追加電力は維持する。

増強の電力は回線16MW・中継容量・発電量を共有し、蓄電所からも補える。増強設備の電力不足は上部の供給率と45秒安定判定にも含む。左の不足数は地区と増強設備を分ける。右で実効/最大出力、送信量、電力の供給量・割合と実際の供給元、増強枠の残りを確認できる。電力ゼロの際は送電経路と発電量を確認する案内を出す。

通信ピークは左に予告し、拡張候補も通常→ピークの需要を表示する。増強操作は既存パケット・進捗・待ち要求を巻き戻さない。回線Undoは設備やピーク設定の変更を戻さない。初期化は増強を撤去するが、ピークの選択は維持して準備時間をリセットする。

## コアと保存

- CommunicationPeaksが設定・起点時刻・増強IDを所有。任意の保存フィールド（CommunicationPeaksEnabled / CommunicationEpoch / BoostedCenters）を追加し、旧形式は無効・増強なしとして読み込む。RulesVersionとGeneratorVersionは維持。
- 保存の時刻・設備を復元してから派生需要と実効出力を再計算する。起点の有限性・範囲、センターID・重複・枠数を検証し、配列を共有しない。プレビューやロードで電力を積分したり安定時間を変えたりしない。
- PowerConsumerで地区と増強センターを共通化。配分・電力診断・蓄電・キャッシュ・品質判定を揃える。PowerFlow.Districtは互換のための旧名で、需要施設のIDを示す。充電は別の記録を使う。
- ピーク中に拡張した直後も、次の運転を待たずに新しい区画のピーク需要を表示・保存する。
- 候補プレビューはクローンだけを変更する。ピーク有効時の参照解は最大需要に必要な増強と蓄電を選び、必要なら合法・予算内の送電専用バイパスで中継負荷を逃がす。最大通信需要を180秒間継続させ、電力ピーク2回と再充電を含めて運転し、品質と45秒安定を確認する。これは無限時間の成立を数学的に保証するものではなく、長時間運転テストと併用する。
