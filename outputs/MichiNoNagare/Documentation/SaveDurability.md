# 保存の耐久性（2026-11-11）

## 調査で分かったこと・未確定のこと

利用中のChromeの127.0.0.1:8766を読み取りで確認したところ、「つづける」がなく、IndexedDB /idbfs / FILE_DATAとlocalStorageは空だった。本編の生成・リセット・保存は操作していない。別ポート8769の同じChromeでは、旧版の初期都市を保存してリロードすると復元できた。Unityで地区別ルール・3シード・拡張3回までのJSON保存39項目も成功した。したがって今回データがなくなった正確な原因は未確定であり、修復したと断定しない。

最後のseed664020296・拡張2回のデータは見つかっていない。ネイティブ版の2026-10-30・seed291026・拡張1回の古いセーブは別ファイルへ保全。本編へ勝手に置き換えていない。

## 変更

- Webでは安定した固定キーのlocalStorageに、主保存と前回バックアップを1回の同期書き込みで保存し、読み返した内容が一致した場合だけ成功とする。破損・保存拒否・容量不足を成功扱いしない。
- 旧PlayerPrefsの読み込みは保持。セーブのJSON・SHA-256形式は変更しない。
- Unity WebテンプレートのautoSyncPersistentDataPathも有効化。
- ローカルサーバーには/api/city-saveを追加。SHA-256付きセーブを検証してwork/city-saves/<port>へ原子的に保存する。ビルド公開先から独立し、過去のスナップショットも残す。ポート別に分け、テストを本編へ混ぜない。他オリジンからの要求は拒否。
- ローカル版の起動時にはPCバックアップを確認し、ブラウザ保存より新しい・同時刻の保存を復元可能にする。unityroom等の外部ホストではブラウザ保存とファイル書き出しを利用する。
- 配線変更・Undo後に保存し、運転中は10秒ごとに保存。タイトル放置・読み込み確認中は自動保存しない。
- 保存失敗は画面上に残す。セーブ管理画面に最終保存とPCバックアップの結果を表示する。
- タイトルとフッターからセーブ管理へ。今すぐ保存、JSON書き出し、JSON読み込みを提供する。読み込みはSHA-256と都市構造を検証し、シード・拡張回数などを表示して明示的な復元を待つ。失敗・キャンセルでは都市を置き換えない。

## 検証

Tools/check-web-save.cjs: JS実装の再起動、主保存とバックアップの組、保存拒否、書き込みが反映されない場合の検出。
Tools/check-server-save.py: PCバックアップの再起動復元、壊れた最新版からの過去データ利用、不正チェックサム拒否。
SaveDurabilityChecks: 地区別ルール、3シード、各3回拡張、移動中データを含むJSONの保存と復元。
