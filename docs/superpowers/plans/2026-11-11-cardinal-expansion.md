**Goal:** Four expansion choices and real, saved terrain constraints, without resetting an existing city.

**Architecture:** Retain the north/south solver and boolean compatibility API. Add a partial core file for lateral generation/routing and sector-owned immutable-in-use obstacle geometry. Make runtime UI and rendering consume this core geometry; add optional save fields with strict validation.

**Tech Stack:** Unity 6000.3.27f2, independent C# core, IMGUI, existing local save bridge and Python server.

## Review questions

Check blocker risks: old south interpreted as east/west; lateral obstacles changing old wire validity; terrain omitted from save/solver; inaccurate affordances for unavailable choices; cloning/candidate generation recursively building offers; heavy 4-direction validation on every GUI repaint; huge frames clipping footer. Offer arrays remain cached until expansion/reset/restore. Bool adapters preserve north/south order and semantics.

## Review resolution

Use enum None=0 for missing legacy direction. Lateral parents are chosen on the outer bank and outside other site footprints; routes use footprint clearance, and two feeders reserve their node pads independently. Demand sites are 6.5 units outward to accommodate the rendering mesh extending in positive X even for westward growth. Saved demand routes must be connected relay chains with unique vertices, legal segment lengths and no restored obstacle crossings. Seed1 placement and a malformed long route were reproduced as failing tests and then fixed. North/south fingerprints match the old implementation across 24 growth steps in both rulesets.
